# 公告分类与判断规则

## 类别

- `course`：上课、调课、停课、教室、带教材或设备。
- `assignment`：作业、材料、心得、论文、报名表、提交文件。
- `exam`：考试、补考、测验、复习、成绩和证书。
- `activity`：会议、讲座、志愿、党团活动、班级活动。
- `admin`：缴费、信息填报、请假、证明、档案和学校手续。
- `safety`：宿舍、交通、消防、校园安全和强制规范。
- `employment`：实习、招聘、就业、考公和岗位转发。
- `resource`：课件、软件、资料、链接和经验分享。
- `noise`：寒暄、表情、闲聊、重复确认、已完成的现场对话。
- `other`：无法可靠归类的事项。

## 公告候选

优先把以下消息或相邻消息段合并为候选：

- 包含“各位同学、通知、请、务必、截止、报名、提交、时间、地点、需要、安排、考试、上课、招聘”等行动词。
- 文本较长，包含日期、时刻、地点、链接、附件或明确对象。
- 连续 20 分钟内围绕同一事项发送的多条消息。

普通聊天、只含“收到/好的/哈哈”的短回复、入群系统消息和孤立表情不进入主队列。

## 重要性

基础分：

- 明确要求全体成员行动：+30
- 涉及课程、考试、材料提交、身份/安全/支付：+25
- 有地点、附件、链接或需要携带物品：+10
- 有明确日期或时间：+10
- 只是推荐、浏览或自愿参加：-15
- 已完成/过去事件：-20

分数截断到 0-100。重要性不是紧迫性；一个下个月的考试可以重要但不紧急。

## 紧迫性

- 截止或事件在 72 小时内：80-100。
- 4-7 天内：55-79。
- 8-30 天内：25-54。
- 超过 30 天或无日期：0-24。
- 日期已过：`deadline_status=overdue`；若内容可能仍需补办，至少 P0/P1 并标记复核。

## 近邻 @所有人 提升

- 默认检查候选消息窗口前后 5 分钟内的群消息。
- 若发现独立消息包含 `@所有人`，且候选本身已判定为公告，则候选最低提升为 `P2`。
- 已经是 `P0` 或 `P1` 的事项不改变；历史事项仍受历史降级规则约束。
- 提升必须保留近邻消息 ID、时间和距离作为证据；窗口可通过
  `--all-mention-window-minutes` 调整。

## DDL 规则

只把带有可定位证据的日期写入结构化 DDL。相对日期需要 `as_of` 才能换算；
只有“尽快、近期、之后”时，保留原文并令 `normalized=null`。

所有 DDL 都应同时输出：

- `raw`：原文片段。
- `normalized`：ISO 日期时间或 `null`。
- `status`：`overdue / due_today / near / ample / unscheduled / reference / unknown`。
  `near` 固定表示距离 `as_of` 1-3 天，`ample` 表示 4 天及以上；没有 DDL
  为 `unscheduled`，只有事件日期而非行动截止时为 `reference`。
- `confidence`：0-1。
