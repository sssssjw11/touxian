# Attention Desk 产品需求与体验重构计划

版本：2026-09-26。本文站在使用者视角定义目标体验；“已实现”与“计划”分开，避免把设计意向写成现有功能。

## 1. 产品目标

作为温州大学的学生，我希望在一处查看微信群聊和各学院官网的新通知，迅速知道“与我有关吗、要不要行动、什么时候截止”，处理后能从待办区移走，并且随时找回已读或归档内容。

产品以**少操作、易读、可信**为优先级，不追求高密度。桌面端是当前交付目标；手机端不纳入本轮验收。

### 成功标准

- 进入工作台后，用户能在 10 秒内识别待处理事项、最近截止项和消息来源。
- 公告标题与正文可直接阅读；正常桌面显示下，主要正文不小于 14px，辅助信息通常不小于 11px，不能靠浏览器缩放才能看清。
- 从官网新公告到原文最多两步；已读内容可在独立“已读完”分区找回，并可撤销已读。
- 群聊事项可一键完成并归档；截止日已过的事项自动退出行动队列，仍保留证据和原判断。
- 所有机器判断有来源、置信度和证据；日期不明确时显示“待核”，不猜成确定截止日。

## 2. 用户任务与信息架构

### 微信群通知

1. 选择本机微信群、导入 `messages.json` 或微信聊天记录压缩包，设消息日期范围和判断日。
2. 选择本地、TypeSafe Jev、DeepSeek 或兼容的自定义 API，发起分拣。
3. 在“进行中”按优先级、截止状态、类别和复核需求筛选；点开查看原文证据与决策轨迹。
4. 一键标记完成并归档；在归档中区分“已完成”和“已超期”，必要时撤销完成。

### 公开来源：温州大学 · 学院官网

1. 检查全部或指定学院，了解上次检查时间与来源异常。
2. 按学院、发布日期范围、搜索词及“全部 / 未读 / 已读完”浏览公告。
3. 打开官网原文时自动标已读，也可单条切换或批量标记；“已读完”只表示阅读状态，不等同于事项已办结。
4. 每条内容显示来源、栏目、**公告发布日期**、分类；按需读取公开正文后显示独立的**活动/报名截止日期**。
   没有可靠来源时明确标“未识别”，不得把发布日期当截止日。

## 3. 功能需求

| P0 | 桌面字号与层级 | 主要正文达到 14–15px，操作与元信息层级分明；长标题和日期不互相遮挡；低动效偏好生效 | 第一轮已实现，待跨分辨率复核 |
| P0 | 群聊截止分区 | 今日、临近、宽裕、未排期动态判断；超期自动归档；人工完成可撤销 | 已实现 |
| P1 | 官网公告分类 | 比赛/活动通知、公示、其他公告三类；可筛选，保留“待确认”避免硬猜 | 已实现 |
| P1 | 官网日期双字段 | 列表显示发布日期；详情按需读取公开正文并显示活动/报名截止日、原文证据和失败原因 | 已实现 |
| P1 | 跨来源行动视图 | 同一任务入口查看群聊和官网真正需要行动的项目；去重不吞掉来源和证据 | 计划 |

## 4. 视觉与交互规范

- 参考 `video-shotcraft` 的 Shot Library：清楚的侧栏导航、搜索入口、Lucide 风格的一致线性图标，以及快速但克制的状态过渡。借鉴节奏，不照搬营销卡片或视频动效。
- 保留当前黑、白、红、黄、蓝、绿的用途：黑色为结构，红色为危险/关键，黄色为临近，蓝色为信息与焦点，绿色为完成。减少无意义的粗边框和重复徽章。
- 正文 14–16px、控制 12–14px、次级元数据 11–12px、页面标题 28–38px；在 1280、1440、1920 宽桌面检查截断、空白和对齐。
- 动效只用于 hover、切换、加载、反馈，通常 120–200ms；不让行高、按钮宽度或列表位置在悬停时跳动；遵守 `prefers-reduced-motion`。
- 图标只保留熟悉的动作语义（搜索、刷新、打开原文、完成、撤销、设置）；不以图标代替状态文字。图标按钮有 tooltip、可访问名称和键盘焦点。

## 5. 数据与判断边界

- 微信数据默认本地处理；远程 API 需用户主动选择并提供密钥。真实聊天原文、密钥、个人画像不提交到公开仓库。
- 学院官网只把公开内容作为来源；认证墙、失败页和部分抓取要显式报告，不能当作“没有公告”。
- `read` 是用户阅读状态，`completed` 是待办完成状态，`deadline_passed` 是时间规则归档。三者不应合并为同一个布尔字段。
- Jev 仅回答有类型约束的窄问题，越界枚举、低置信度和远程提供的截止日期/紧迫性覆盖都要拒绝；保留人工复核入口。
- 官网新公告首次扫描的历史内容默认已读，后续新增才进入未读。重扫不应重置用户已读选择。

## 6. 分阶段实施

1. **可读性与找回**：官网已读完分区、计数与空状态；全站字号基线、细微动效、键盘焦点；构建和核心状态回归。**已完成，待持续做跨分辨率验收。**
2. **官网信息补全**：抽取/展示发布日期与可验证的活动截止日，建立三类公告判定和人工复核样本；正文按需读取，覆盖 22 个来源。**已完成。**
3. **结构减重**：把超长 `App.jsx` 按数据源、队列、详情、设置拆分；提取共用日期/状态格式化与列表控件。每次拆分前后比较同一组交互，不同时修改判断规则。
4. **体验收束**：桌面多尺寸截图、键盘路径、慢网络和失败来源、空列表/大量列表复核；以实际任务完成时间和误操作率检查改造收益。

当前轮不改动 Jev 算法、抓取范围或跨来源数据模型；这些需要样本与来源合法性验证，不能通过视觉重构顺带改变。
