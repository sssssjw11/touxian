日期：2026-09-30。基线：1.24 / versionCode 25；目标：1.25 / versionCode 26。保留 1.24 的群名恢复修复，本轮仅本地更新，不提交或推送 GitHub。

## 工作计划

1. 区分会话范围关键词与消息正文关键词，不让新增消息规则扩大观测范围。
2. 增加关键词、事件类型、重要性、启用状态的本地规则管理；微信事件监测更多菜单和 APP 设置均有入口。
3. 将规则加入同一事件引擎，标记命中依据；保存后当前屏重新分析，不与内置规则产生重复事项。
4. 核对否定、完成、转述与停用规则，不把已取消事项改成紧急待办；意图模式不自动写事件，云端不改写用户明确设置的类型和重要性。
5. 核心、服务和页面针对性回归，构建并真机验证规则管理及真实消息命中，保留原有数据。

## 实施记录

- 已完成规则模型、JSON 本地配置、消息匹配与管理页。每条规则包含正文关键词、事件类型、P0–P3 重要性、启用状态和稳定 ID，最多 100 条。
- 微信入口为「事件监测 → 更多 → 消息关键词」；APP 入口为「规则与外观 → 消息正文关键词」。支持新增、编辑、启停、确认删除和旋转时保留编辑草稿。
- 使用字面匹配、NFKC 规范化和英文单词边界，不执行用户输入的正则表达式；只匹配对方的原生文字节点正文，不匹配会话名、发送者、自己消息或未核对 OCR 正文。
- 已接入服务规则变更监听、微信更多菜单入口、诊断规则数量。诊断不导出关键词内容。
- 已编写当前页面规则变更后的即时分析与意图模式隔离回归。
- 自定义规则接入原事件引擎，事件 ID 保持兼容，不另建重复保存通道；命中依据保留在事件详情。用户选择的类型和重要性不被云端结果覆盖。
- 已有事件不因删除/停用规则自动删除。普通关键词命中默认作为可关注信息，只有明确行动要求才成为需要行动的事项。
- 对抗检查修复：事件不存在的否定表述不触发任务，保留缺水断电等实际信息；无关引用不抢夺正文任务；已取消的高优先级关键词不覆盖同条消息中的另一项有效任务；已过期的用户 P3 规则不被提升到 P2。
- 共享行动判断补充「不用/无需/不需要提交」等否定形式，保留「无需打印但需要线上提交」中的实际要求，并回归意图引擎。
- 首轮 179 项测试中 5 项编辑页失败：保存监听原先依赖异步 OnShow 回调，部分测试在回调执行前点击保存。改为 show 后同步绑定，测试同时正确驱动确认按钮的主线程回调；新增不等待回调的第一次保存测试，避免只靠测试等待隐藏竞态。

## 边界

- 消息关键词不扩大已选择的会话范围，也不替代可靠会话名称的读取。标题 OCR 仍受截屏权限、顶部截断和文本误读影响。
- 六次真机滚动检查时原生标题均可读；标题为空后的真实 OCR 恢复仍待该页面状态再次出现验证，不能把代码回归等同于真机结果。
- 用户配置的类型和重要性是规则偏好，不是概率或模型置信度；完成、取消、过期仍保留低优先级观测和原始依据。
