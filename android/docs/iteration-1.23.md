# 偷闲 1.23 工作计划与实施记录

日期：2026-09-30。基线：1.22 / versionCode 23。目标：1.23 / versionCode 24。

本文保留当时的本地开发与未验收状态；后续公开发布统一收录在 [1.25 更新与 Debug 记录](releases/v1.25.md)，其中区分了后续真机结果与仍待验证项。

## 目标与验收

让识别结论、保存动作与 APP 展示保持一致；新增单会话聊天记录和可追溯的关系深度分析；遇到故障时可导出诊断。优先常用流程与有效测试，本轮没有真机环境，不以代码测试代替真机验收。

| 工作 | 实施方式 | 验收 |
| --- | --- | --- |
| 群名与范围识别 | 核对真实标题节点与顶部候选，排除消息内昵称，修正关键词边界 | 节点构造与标题、关键词回归 |
| 意图、情绪与事件 | 否定、已完成、引用、多人上下文隔离；检查置信度来源及重复权重 | 对抗样本不能相互串台，明确请求与情绪不漏判 |
| 单会话记录 | 微信意图模式显式开始/暂停/结束；切会话、锁屏、模式切换时暂停；沿用本地消息库 | 只写选定会话、重启不自动继续、不创建自动事件 |
| APP 深度分析 | 选择录制、消息日期范围、未知日期；全量统计、关键语境和原话证据；可选 DeepSeek 深化 | 本地离线可用；分析与所选日期绑定，新增消息使旧报告失效 |
| 关系判断 | 借鉴 she-love-me 的统计与证据方法；分开双方/多人，不把情绪等同关系态度 | 边界优先、低样本低置信；不把采集时间伪造成回复时间 |
| 识别到保存闭环 | 记录本地判定、事件提交、列表筛选；悬浮窗显示数据库合并后的状态 | 已归档/已完成状态不被新识别假装成新事件；意图模式有手动保存事项 |
| 可导出诊断 | 系统文件选择器导出 JSON：版本、权限事实、心跳、读取/存储/列表阶段和统计 | 不需文件存储权限；可定位未创建/写入失败/筛选隐藏 |
| 动效与产品一致性 | 复用现有图标、字号、透明度与短动效；录制状态紧凑显示 | 模式操作不会交叉执行，快速点击不叠加挂窗/动画 |

## 本轮边界与默认值

- 继续只支持 WeChat，保持本地优先；不引入微信数据库解密或 QQ/飞书功能。
- 意图模式默认不自动创建事件、不保存聊天。用户显式开始后才记录；手动保存事项是独立命令。
- 记录当前可见消息及用户自行滚动的页面，不宣称获得完整历史。日期选择使用消息日期，未知日期单列。
- DeepSeek 深化由用户单独点击确认，先保留本地报告；失败不覆盖本地结果。
- 关系评分是可解释线索，不是恋爱概率或人格诊断。群互动不强行解释为两人关系。
- 测试围绕变更和已证实缺陷，不反复进行无关的全面安全测试。
- 本轮代码、文档与 APK 仅保存在本地，按用户要求不提交、不推送 GitHub。

### 1. 环境与依据检查：已完成

- 检查 1.22 捕获服务、消息 SQLite、事件 JSON 原子写入、悬浮窗、配置与测试结构。
- 读取本地 she-love-me 分析框架与上游统计/采样代码，采用“全量统计 + 关键窗口 + 原话证据”的方法。
- 检查用户提供的 8.4 秒录屏：期间切换为意图分析，之后 APP 事件数为 0。按照原设计该模式不自动创建事件，不能据此确认权限不足；该反馈需要模式解释与写入诊断。
- 恢复本机 J: 工作目录映射与忽略的 local.properties，统一使用 ASCII 工程路径运行 Gradle，解决中文路径下测试启动器无法加载类的问题。没有把该环境调整纳入提交文件。

### 2. 识别修复：已完成代码回归

- 修正完成/否定/转述动作、他人关闭语句覆盖当前请求、他人行动抬高当前置信度。
- 修正否定与引用的情绪归因，同词重复不持续累计，明确询问对方感受不归为说话者情绪。
- 修正事项更正的连续性，排除标题 fallback 从消息列表误读昵称的路径。
- 降低置信度过早饱和；结合具体程度、上下文距离与歧义计算分差，不将评分称为校准概率。
- 关键词匹配保留 ASCII 词边界；录制、标题绑定、关系分析使用独立的严格会话身份比较，避免 A-B/AB、张 三/张三等误合并。正常标题末尾人数变化仍可兼容。

### 3. 记录与分析：已完成本地实现与回归

- 新增录制元数据与本地消息库版本 3，保留旧消息，补精确消息时间字段。
- 新增录制服务与 APP 会话分析页、报告保存和日期选择；关系本地分析与对抗样本已实现。
- 可选 DeepSeek 深化已接入确认、取消与失败回退；发送全量统计和最多 90 条关键消息，模型引用必须匹配提供的原话。明确边界、群聊和低样本情形不能被模型改写为相反的关系结论。
- 意图分析本身仍不要求会话名称；显式开始记录时才需要确认名称。切换页面、锁屏、模式切换与重启暂停记录，继续需用户确认，不自动追踪另一个会话。
- 快速屏幕更新进入有界、有序保存队列；重复页不会阻断排空，旧写入回调不会清空新任务。队列溢出明确暂停，不默默丢弃后继续显示“记录中”。
- 同日相同原话但不同已知消息时间不再错误去重；新消息使旧报告失效，日期筛选以消息日期为准，不以采集时间伪造历史。
- 微信悬浮窗保留半屏宽上限；意图模式底部精简为录制、刷新、更多三个图标，菜单替换详情而非一起堆叠。禁用系统动画时按压效果不继续缩放。

### 4. 诊断与闭环：已完成本地实现与回归

- 已新增识别、事件写入、页面显示阶段记录及结构化诊断导出入口。
- 意图模式新增“保存当前事项”，不偷偷切换模式；已确认事件不会因立即打开 APP 而取消落盘。APP 已打开时，事件稍晚落盘也会自动刷新列表。
- 悬浮窗显示实际合并保存的事件状态，避免把已完成/已归档事项又显示成新待办；录制暂停和删除竞态不会重新创建已删除录制。
- 导出入口：APP 微信采集页的诊断区域。系统文件选择器导出 JSON，记录版本、实际权限、心跳、最近 80 条阶段元数据与数量，不含聊天正文、会话名、截图或 API 密钥。

## 已知边界与后续验收

- 相同显示名称不等于相同微信会话 ID；当前只能严格核对名称并在微信导航变化时暂停确认，不能承诺区分所有重名联系人。
- 记录仅覆盖读到的消息，暂停/结束取消尚未提交的旧任务；已保存部分保留。该功能不是完整微信历史导出，不能据此推断对方沉默时长或精确回复延迟。
- 修复已有可复现规则样本，不承诺任意新语境全部正确；真人情绪与关系结论仍需结合可追溯证据查看。
- 首次真机验收优先重放用户反馈：事件监测识别后的 APP 入库、意图模式手动保存、同会话跨屏录制、切换同名联系人后的暂停、诊断导出。失败时导出诊断再针对阶段修复。
