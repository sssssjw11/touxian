# 偷闲 1.21：会话确认与常用功能修复

## 群名与来源

- 手动标记先等待微信聊天信息页，按“群聊名称”所在行读取完整名称，不再拿页面上的第一个摘要值。
- 读取失败才转本机标题 OCR；带省略号的结果不直接绑定，确认页可填写完整名称并显示识别来源。
- 不再将连续出现的单一发言者头像昵称当成群名。
- 标题绑定使用整屏消息的有序重叠、发送者、消息类型和已知日期；窗口重建不再单独导致失效。
- 可读标题发生冲突立即释放旧绑定。离开聊天后，普通的“收到”等回复不足以恢复绑定。
- 各次手动标记独立校验请求代次；旧回调、暂停后的回调不能打开错误确认页。
- 识别词条忽略零宽空格和 BOM，保留原有全半角、人数后缀及拉丁词边界处理。

## 已知失败用例修复

- 正文明确类别优先于群名；只有正文没有明确类别时才用群名补充。黑客松群内的课程作业仍归课程，学分通知仍归教务。
- 仅含“28号”等日号且没有消息日期时，保留日期待核对，不借观察日猜月份。
- 明确已截止的日号向过去解析，不再滚动成未来待办。
- “路演要讲多久”等无问号口语问句可以进入解释类判断；“用不了多久”等陈述保留反例。
- 批量归档改为两行操作区，全选、已选数量、退出在第一行，归档命令单独一行；全选仍覆盖当前筛选结果，不限于已加载的 20 条。

## 验证边界

本轮聚焦标题链路、日期、分类、口语问句、归档布局。未扩展其他聊天平台，未改模型权重，未做全量安全测试。真实情绪准确率和置信度校准仍需匿名标注样本评估，不能用单元测试通过替代。

无障碍树缺少会话唯一标识时，消息重叠只能提供连续性线索。完全换屏、只有通用回复、服务重启后，仍可能需要重新标记；不会承诺所有群名都能自动确认。
