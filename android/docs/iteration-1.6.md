# Attention Guard 1.6 迭代方案

目标：让“发现重要事项、核对依据、完成行动”在三分钟演示和日常使用中都可信。
本文件同时记录 1.6 的交付边界。没有真机条件的条目仍保持“待验证”，不把本地测试当作设备通过。

## 已交付（1.6 本地验证）

- 记录页增加质量回执：总数、重复候选、日期未确认和回溯分页断点。
- 诊断页改为结构化状态行，区分服务连接、读取质量、落盘、悬浮窗和保活通知；完整文本仍可复制。
- 日期选择器即时反馈非法范围，并限制结束日期不能晚于今天。
- 事件详情增加“为什么是这个等级”摘要，明确本地证据门槛优先于 DeepSeek。
- 版本升级为 `1.6 / versionCode 7`。

本地交付证据：Gradle 单元/Robolectric、lint、APK 元数据检查。真机回归仍受 ADB 不可用影响。

## 第一优先级：判断可信

1. 多事项分段：同屏两个通知分别提取，不把更正、询问、转发混成一个事件。
   使用脱敏合成语料构造至少 60 个场景，分别报告 P0 误报、漏报、日期解析与更正命中率。
2. 旧记录重审：提供“预览变化、逐条确认”的重审流程，不静默删除、改级或覆盖完成状态。
3. 时间置信度：将确定日期、推断日期、未知日期存为结构化字段；消息日期缺失时不借今天推算。
4. 事件身份：通知内容、来源和已知消息日期共同参与匹配；相同群名由用户确认，不能冒充唯一会话 ID。

## 第二优先级：采集可靠

1. 回溯质量回执：展示新入库、邻屏复用、未知日期、疑似重复与缺口，提供可定位的人工核对入口。
2. 持久化重叠索引：扩展 1.5 的短时同屏重放防重；先验证误删风险，再考虑跨任务匹配。
3. 长时场景：连续 30 分钟、锁屏/解锁、断网、低存储、进程重启、微信版本变化，记录耗电与恢复时间。
4. 设备矩阵：至少增加 Android 13/15 和另一厂商；自动翻页方向、停机响应和日期边界逐项验收。

## 第三优先级：演示与视觉

1. 演示采用明确标注的内置样例：通知出现、日期更正、等级变化、查看依据、完成/恢复。
   无需真实聊天、真实密钥或联网，不能把样例状态伪装成实时采集。
2. 紧凑条吸边与位置记忆：单手拖动、旋转/键盘避让；不增加常驻装饰动效。
3. 自适应字体与深色主题：重点验证 320dp、200% 字体、TalkBack 顺序、暂停控件可达性。
4. 发布工程：签名 release、升级/回滚演练、隐私清单、依赖许可与真实截图脱敏审查。

## 演示验收线

- 从授权群进入到出现可见状态、从暂停到停止翻页，都必须有真实时间记录。
- 任何 P0 都能看到具体行动、有效截止时间和原始依据；未知信息明确标出。
- 回溯被打断后已有记录仍可查看，不偷偷恢复滚动。
- 演示失败时可进入诊断，界面不显示虚假的“正常运行”或完整历史百分比。
