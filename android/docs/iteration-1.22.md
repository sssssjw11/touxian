# 偷闲 1.22：表情线索与真机回归

日期：2026-09-27。延续 1.21 的群名与常用功能修复，只增加与本次真机问题直接相关的调整。

## 本轮修复

- 识别微信以文字输出的标准表情，如 `[发怒]`、`[流泪]`，以及相应 Unicode 表情。
- 表情单独显示为“负向表情线索”“积极表情线索”或“调侃表情线索”，不直接断言对方真实感受。
- 单纯表情证据的规则置信度上限为 58%；重复同一表情不提升置信度。
- 同时出现明确情绪文字时，独立文字线索可以提高把握度。括号内文字不会再与表情重复计数。
- 自己的表情不算作对方情绪；已知不同群成员的文字也不混入当前发言者的情绪判断。
- 上文衰减距离按真实消息位置计算，选取较近证据；不再因先过滤发送方而失真，也不优先截取最早的八个线索。
- `[微笑]` 等歧义表情及未知图片占位符不强行推断；未对自定义表情图像执行视觉理解。

## 验证与后续

136 项针对性测试及 19 项已安装 APK 设备规则检查通过，真实聊天中的 `[发怒]` 已出现 46% 的负向表情线索。详情见 `device-acceptance-1.22.md`。

仍需后续验证或改进：

1. 标题不可读时，“聊天信息页取全名 → 确认 → 返回 → 绑定 → 切会话释放”的完整真机流程。单测已覆盖，但不能代替端到端结果。
2. 规则置信度不是经标注数据校准的统计概率。应继续积累去标识样本，检验反讽、表演性生气、安慰、混合语气及多人对话归属。
3. 保留对未知图片表情的低把握线索；不把“没有可读文本语义”误写成已经理解图像。
4. 历史识别词条中可能仍有旧版本 OCR 的截断项。新版本阻止新增省略名称，但不擅自删除用户已有词条；可在来源设置核对。

没有新增其他聊天平台，没有声称训练了模型权重，没有扩大到全量安全测试。
