# 手机端意图分析与对象档案 1.26.1

这次迭代把 1.26 已接入的能力补成连续流程：从首页进入档案，明确关联会话，在当前消息中看解释与回应，再更新有原文依据的沟通画像。

## 用户可见变化

- 首页增加对象档案入口。列表可按名称、关联会话或档案编号末六位查找，卡片展示场景、对话类型、记录与消息数量、画像状态。同名对象仍有独立 ID。
- 自由分析增加四种场景、本地语境解释、其他解释、澄清回复、原文依据和手动 DeepSeek。按「我：」「对方：」分行输入；长正文和消息数量受现有实时预算限制。
- 实时悬浮卡在本地即时判断之外展示有原话支持的候选解释与回应。同一会话的新消息不再关闭建档或选择档案的表单；切换聊天、切换场景或退出仍撤销旧操作。
- 档案首屏优先显示更新状态与分析入口，取消按钮只在工作期间显示。记录新消息后可看到新增数量和上次更新时间；过期摘要可手动回顾，不能进入新分析。
- 从会话页关联档案后直接返回当前会话并采用档案场景。转移已有关联的记录、解除关联均有明确影响说明和确认。
- 报告按明确表达、可能诉求、沟通画像、互动模式、需要留意和回应建议筛选；本地统计默认收起。本地画像可以提取对方明确表达的交流需要，风险仅提示可核对的具体措辞。
- 原文弹窗突出引用位置，显示录制来源，并可展开同一录制中的前后两条消息。前后文可能存在采集缺口，不能被当作完整时间线。
- OCR 识别内容保留待核对标记，不能直接生成沟通画像或作为 DeepSeek 原文发送。
- 实时、自由分析、会话与档案共用发送确认组件，显示实际条数、字符数、截取标记及可展开的完整发送片段。确认前不会发送请求。

## 分析与存储

应用版本为 1.26.1 / versionCode 29。SQLite 仍为版本 4，未增加或移动消息表。1.25.2 升级时继续执行 v3 → v4 的原有迁移。

分析结构版本从 2 升至 3，包含本地语境与明确沟通需要的提取变化。旧对象画像标记为待更新，上次摘要仅供回顾；只有与当前原文、场景、关联和分析版本匹配的画像才进入后续请求。旧会话报告仍能打开，并提示更新分析方式。

档案报告保存 sourceMessageCount 与 analyzedAt，均为可选字段；旧结果无需补写。每次生成画像重新读取关联原文，历史总结不累积为事实。

实时及自由分析默认不落盘。只有用户明确录制、关联和更新档案的内容进入 SQLite。DeepSeek 继续使用现有密钥、网络传输、引用校验与取消实现，未增加手机端依赖。

## 请求与界面有效期

- 模型请求绑定消息内容、场景、档案版本与页面代次。自由分析编辑原文、换场景、取消或进入后台后，旧响应无法覆盖页面。
- 建档和对象选择另以聊天及用户操作的有效期检查；同一聊天新增消息可以继续填写，换聊天后回调失效。
- 新消息、原文修改、删除或解除关联使旧画像失效。保存前仍在数据库锁内复核原文和取消状态。
- 离线或 429 后保留本地分析并恢复重试按钮。模型不得改写全量本地统计、发送者或原话。

## 验证与设计依据

界面改动先沿用现有 GuardUi、字体、色彩、图标和 Android Views，再对比 1.26 与新版的八个实际渲染状态。截图来自 Robolectric 的 Android 原生图形运行时，使用示例聊天；不代表物理手机或微信现场验收。

设计问题、前后截图和检查范围见 [手机流程检查](design/1.26.1/review.md)。构建、签名和交付信息见 [1.26.1 升级说明](releases/v1.26.1.md)。

仍需手机验收：覆盖安装、输入法与返回手势、悬浮球/紧凑/展开三种尺寸、长内容滚动、微信实际滑动时的标题绑定与闪烁、真实 DeepSeek 响应。自动化不替代这些检查。
