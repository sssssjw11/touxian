# Attention Guard 1.4 微信采集复测

## 本轮对照

对照的是参考仓库提交 `d8720521fa13aa5172a891cba95c5dd8aeb44a11`，不是把远端代码直接覆盖到当前产品：

- 参考采集服务（历史版本） 读取前台聊天界面的无障碍树，新版另有截图 OCR 分支。
- 参考适配器（历史版本） 使用微信气泡 ID `com.tencent.mm:id/bkl`，并区分非聊天页和有气泡但无正文的情况。
- 参考项目中的输入框写入是“填入回复”功能，并非采集机制。Attention Guard 不移植该写入功能，读取时也排除编辑器内容。
- 历史注册类名保持不变以兼容已有授权。参考项目注释中的个别版本实验不能证明当前手机兼容，更不能证明无微信风控风险。

## 已修复的链路缺口

| 旧行为 | 1.4 行为 |
| --- | --- |
| 只看活动根，根暂空就结束，缺少恢复检查 | 区分应用/键盘/无障碍浮层，短节流加周期恢复，锁屏与其他前台应用阻断 |
| 自动模式等分析结束才显示，失败原因不可见 | 识别时显示状态；不可读也能打开诊断；保留上次挂窗结果 |
| 单一 ID 的直接文本，群名最多 24 字 | 读取可信气泡的子节点，放宽群名长度，并增加有条件的结构匹配 |
| 普通聊天未产生事件，等于没有任何记录 | SQLite 单独保存可见消息，本地事件与云端整理不再阻塞原始消息归档 |
| 昨天的时钟可能解释为今天 | 只解析完整时间分隔标签，处理相对日、星期、中文/数字日期；无证据标为未知 |
| 没有可控的日期回溯 | 指定会话与日期，二次确认开始，手动默认，慢速自动为可选 |
| 没有正文被隐藏后的替代入口 | 默认关闭的本机中文 OCR，只对有可靠气泡证据的空正文启用 |

## 安装与首次验证

1. 使用 `app/build/outputs/apk/debug/app-debug.apk` 覆盖安装，版本应显示 `1.4`。优先保留数据，不要为解决签名冲突直接卸载。
2. 在系统无障碍中关闭再开启 Attention Guard 一次，让新服务配置重新绑定。没有授权就不会开始采集。系统提示“受限设置”时须由设备所有者在系统设置中处理，应用不会自动授权。
3. 在“我的”开启观测；DeepSeek 可不配置。系统省电、自启动、通知权限按手机实际情况设置。
4. 打开自己有权查看的微信群，停留几秒。正常状态为群名、可见消息数；不必等待收到新消息。
5. 返回“来源 → 采集与回溯”，检查“消息记录”。普通聊天也应可见；观测簿只显示命中规则的事件。
6. 无记录或无浮层时，点“复制诊断”回传。它只含服务状态、节点/消息计数、时间、微信版本及设备信息，不含群名、正文、截图或密钥。

采集使用无障碍浮层，另一项“应用悬浮权限”不是该链路的前置条件。返回应用时显示“悬浮窗已隐藏”是正常的，应同时查看“上次挂窗”。若系统持续断开无障碍，先处理该连接问题，不要直接开启 OCR。

## 按日期回溯

1. 最好先停在所需结束日期附近、或该会话最新消息处。应用不会替你搜索日期、进入别的群或自动跳到聊天底部。
2. 从微信悬浮窗点“采集与回溯”，会预填刚识别的完整会话名称。从来源页进入时需填写微信实际显示的名称，包括可见的群人数后缀。
3. 选择起止日期，两端都包含；结束日期不得在未来。保持自动翻页关闭即为手动回溯。
4. 点“准备回溯”并确认，然后返回目标微信会话，在浮层点“开始回溯”。仅准备不会执行翻页。
5. 自动模式只向已确认的消息列表发送 `ACTION_SCROLL_BACKWARD`，至少间隔 4 秒，并等待当前页落盘。没有坐标盲滑、输入、粘贴或发送操作。
6. 浮层提供暂停/结束；关闭浮层、离开微信、锁屏、换群、读取失败、保存失败或控件不支持翻页时停止自动操作。恢复必须主动点击。应用重启不继续任务。
7. 单任务最多 200 屏/200 次翻页或自首次开始起 15 分钟，暂停不重置时限。达到上限可结束后另建任务，不会无期限自动运行。
8. 在“本次回溯”查看归档及未知日期数量。清空消息需要确认，会同时关闭观测，且不删除独立的事件依据。

### 不能视为完整备份

- 日期来自微信实际暴露的分隔标签，不是消息数据库里的精确时间。标签不存在的消息以“日期未确认”保存，不计作已经确认命中日期范围。
- 只有全屏消息都有已知日期且都早于开始日期时，才标记到达起始边界；这不表示覆盖了完整目标区间。
- 相邻页面有明确顺序重叠才合并。单个“收到”等相同文本不是唯一身份；无法拼接会保留并提示缺口，可能出现重复或遗漏。
- 同名群、群名变化、跨年日期解释、局部气泡被裁切、被删消息、未加载历史、跨任务/重启，都是完整性与身份限制。
- 慢速翻页能降低操作频率，但不存在可由本项目承诺的“零风控”速度。遇到微信限制或异常提示应停止，不尝试绕过。

## 正文不可读时的 OCR

在“采集与回溯”中单独确认开启。本版使用 [ML Kit 内置中文模型](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)，无需等待首次下载语言模型。截图仅存在内存，只把已确认气泡区域送入本机识别；不保存或上传截图。识别结果标为“OCR 待核对”，不自动提取事件、不送到 DeepSeek。

同一布局成功识别后不反复截屏，失败最多重试 3 次，尝试间隔至少 8 秒；滚动、切换页面或“重新读取”可重新触发。完全不暴露气泡节点、窗口被系统保护或截图权限不可用时，该方案也无能为力。历史任务在正文不可读时暂停，不用 OCR 结果推动自动翻页。

基础能力使用 Android 的 [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)。是否真正暴露节点、允许截屏、支持列表滚动和长期运行，必须在目标微信版本与手机系统上验证。

## 需要回传的结果

- 进入微信后的浮层状态，以及诊断文本。
- 普通文字消息是否保存，群名/发送者/左右归属是否正确。
- 手动回溯的日期是否正确；自动翻页方向是否朝更早消息，暂停是否立即停止下一次翻页。
- 开关权限、键盘、锁屏、换群、返回应用时的表现。

无需发送真实聊天正文、密钥或全屏聊天截图。当前开发机没有 ADB 设备，本轮自动化不构成真实微信端到端验收。
