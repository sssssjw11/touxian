# 1.26：手机端语境深化与对象档案

基线：1.25.2 / versionCode 27 / 提交 71c2342。交付版本：1.26 / versionCode 28。

## 使用路径

1. 微信悬浮窗切换到「意图分析」，展开后点「深入理解」。
2. 先查看发送范围，确认后才请求 DeepSeek。首屏是简短结论，「解释与原话依据」展开事实、可能诉求、其他解释及引用。回复只复制到剪贴板，由用户决定如何使用。
3. 更多菜单提供「分析场景」「为当前对象建档」「选择当前对象档案」「管理对象档案」。场景为通用、朋友、工作、亲密；新档案默认通用。对话类型未确认或群聊时不生成个人画像。
4. 新建档案需确认当前会话名称。「建档并开始记录」明确启动记录并关联该录制 ID；正在记录时关联现有记录。后续新增消息使已有画像标记为待更新。
5. 下一次打开聊天要手动选档案，显示名相同不会自动复用或合并。选择档案时如有当前正在记录的会话，会展示关联及转移说明。
6. APP「会话分析」可切换本次分析场景并「关联对象档案」。列表的「对象档案」入口可管理独立档案。
7. 档案页可编辑名称、场景、对话类型，关联多份录制，解除关联、更新本地画像、请求 DeepSeek 深化或删除档案。删除档案保留原始录制和消息。

## 共用分析结构

- AnalysisScene / ContextInsight / ContextSection / ContextEvidence / ReplySuggestion 供实时、会话和档案共用。
- 明确表达、可能诉求、沟通画像、互动模式、风险线索分开；每项判断含原文、证据充分程度和必要的其他解释，允许明确写依据不足。
- 实时引用使用请求内 live: 标识；历史引用使用 archive: 数据库消息 ID，同时保存来源、发送者和已确认日期。采集时间不会补成消息时间。
- 画像更新重新读取已关联原文。已有总结仅可作为实时背景，不能成为新增证据或累积置信度。
- DeepSeek 必须返回结构化 JSON。引用 ID、逐字连续原话、side 和 sender 必须匹配本次实际发送的原文，截断部分之外的引用也会拒绝。
- 本地统计、明确边界和群成员区分保留；低样本、单侧消息和群聊仍可展示有依据的局部澄清与建议。禁止把明确拒绝反解成喜欢或试探，新增校验抑制明显反转措辞；模型语义仍需用户回到原文核对。
- 不加入 skill 的失衡公式、恋爱概率、固定心理标签或角色口吻。沿用旧报告的本地统计字段，数值仅为已有规则线索。

## 发送预算与取消

- 实时：最多 20 条当前可读消息，关联档案时最多 6 条历史依据和 1,500 字符新鲜摘要；正文加摘要最多 16,000 字符。为历史依据预留部分预算。
- 深度：完整选定范围统计，最多 90 条关键原话，正文最多 40,000 字符。采样保留近期、边界、冲突及修复附近消息；长消息发送受预算限制的前缀并标记截断。
- 仅可读 nodes 文字或具名表情作为云端原文依据；图片、语音和 OCR 猜测不变成云端证据。
- 实时深化结果不落盘。录制、会话报告与档案结果按用户明确保存的流程处理。
- 实时请求绑定消息签名、场景、所选档案和档案内容版本。切换聊天、改消息、改场景、换模式、取消或关闭时递增代次并断开连接；已排队的旧响应不更新悬浮窗。
- 会话与档案写入在数据库锁内重新核对原文、范围、关联版本与取消状态。失败保留本地结果并可重试。
- 复用现有 DeepSeek 密钥与网络实现，实时读超时 45 秒，深度 90 秒；取消断开连接，不需等待超时。

## 升级与存储

- message_archive.db 从版本 3 升到 4，新增 conversation_profiles 与 profile_recordings。
- 原 messages、recordings、screen_checkpoints 及其 ID、消息和报告不移动、不重建。
- 档案有独立 UUID，每份录制最多关联一个档案；转移关联会令两侧已有画像失效。名称只用于显示和选择。
- 缓存包含原文内容、side、sender、日期/时间、录制 ID、范围、场景、关联档案及版本。新增、改写、删除原文或编辑/解除档案关联后，旧画像不再作为新鲜报告使用。
- 档案分别保存本地和云端报告；旧会话结果格式继续可读取，按原有范围与内容指纹校验。
- 使用 Kotlin、SQLite、Android Views 与现有 Material 控件；未新增手机 Python 或本地大模型依赖。
