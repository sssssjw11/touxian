# 1.19 迭代：微信有用消息识别

## 本轮目的

针对现场漏判，把“读到了消息”与“识别出有用事项”分别验证。事件监测应提供事件类型、大致内容、重要性、后续动作和原始来源，而不只看是否含有某个提醒词。

## 功能修正

- 共享 `NoticeRules`：事件监测与意图分析使用一致的行动、信息、取消和例外条件信号。
- 增加“班会 / 会议”类型；同一发送者、日期兼容的会议通知与后续提醒可合并，保留会议时间和消息依据。
- 同屏多个独立事项分别生成事件，一次写入本地台账；悬浮窗优先显示最重要的一项。
- 保留学分进度、招聘宣讲等有用信息，不把没有行动要求的信息强行标为待办。
- “已申请的同学不用重复填写”等局部豁免不再取消整条行动通知；普通回复、裸提及和闲聊保持过滤。
- 解析“今晚七点”“今晚7点半”“明晚七点一刻”“今天下午13:30”等时间。相对日期依赖消息日；含糊时间仍需核对，已过期事件不提升紧急级别。
- 意图分析跟进相同发送者的相关语境，避免另一位成员的闲聊借用会议行动要求。
- 本地事件不再因为没有达到通知门槛而完全不展示；等待云增强时保留本地结果。云增强只使用所选事件的相关消息。
- 本地异步结果展示前核对当前画面签名，避免切换画面后显示旧结果。

## 样本与构建

- 新增匿名化校园通知回归样本，覆盖班会、填表、学分、重修、招聘、取消和反例。
- 这是本地规则校准与回归测试，不是模型微调或训练。
- 固定使用 `J:\` 项目路径构建；Gradle 用户目录与临时目录使用 `L:\` 下的 ASCII 别名路径。
- 本轮已执行清理构建和 `--no-build-cache`；使用 `scripts/verify-apk.ps1` 核对交付 APK 含有新规则。
- 新增 `scripts/DeviceRuleCheck.java`，可以直接对手机安装包运行核心规则检查。
- 版本：`1.19` / `versionCode 20`。

## 验证与后续

95 项定向测试和 9 项已安装 APK 的设备端规则检查通过。完整边界、包哈希与待验收项目见 `device-acceptance-1.19.md`。

新版本微信界面仍待手机手动解锁后实测。后续优先收集实际错例，记录期望的类别、重要性与时间，再加入回归样本；不宣称有限样本等同于所有群聊准确率。
